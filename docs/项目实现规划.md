## 数据核查

`questions.jsonl` 有 50 题、87 条证据，默认基线使用其中 42 道主评分题和 80 条证据，另存于 `retrieval_questions.json`。当前 211 条切片覆盖 27 个版本，切片文件与 SQLite 中的切片 ID、版本、正文和正文哈希逐条一致。完整题集证据按版本限定并规范化引文后，均各自唯一命中一条切片。证据的路径和来源哈希与版本清单一致，证据版本在题目指定日期有效。数据库中的 6 个评测用户已启用，现有权限检查脚本通过。

## 设计

- 共享评测默认使用 42 题检索集，可指定完整题集运行诊断。从证据的版本、来源定位和引文生成切片级标签，校验映射与当前切片快照。映射缺失或歧义时应报错并人工核对。多条引文命中同一切片时，切片计一次。参考答案、目标版本和证据仅用于评分。
- 共享候选范围从 SQLite 获取可信用户和制度授权，复用 `can_read_document`，按左闭右开的版本有效期筛选。指定制度查询进一步限定到显式指定的制度。权限、日期和指定制度范围都在候选截断前生效。
- 关键词检索对查询和切片统一做 NFKC 规范化和小写化，中文使用相邻双字切分，保留制度编号与数字。BM25 使用候选集的词项统计，参数为 k1=1.2、b=0.75，仅返回正分切片，同分按切片 ID 排序。检索模块返回切片 ID、制度版本、分数和来源定位，供评测及后续混合检索复用。
- 向量检索复用切片入库时的本地 BGE-M3 编码器，对原始问题生成归一化的 1024 维稠密向量。使用同一个 `resolve_scope`，把允许的版本作为 Qdrant 查询过滤条件，再按余弦相似度精确检索。评测启动时逐条检查 Qdrant 与 SQLite 的切片 ID、版本和正文哈希，并核对编码配置，发现索引与当前语料不一致时中止。
- 混合检索将同一原始问题和候选范围传给 BM25 与 BGE-M3，各取前 20 条。按切片 ID 合并两路结果，每一路第 r 名贡献 `1 / (60 + r)`，缺席的一路贡献为零。按融合分数降序排列，同分按切片 ID 升序排列，再取 Top-K。
- 每题取一次 Top-10，再切出 Top-3 和 Top-5。36 道完整回答题、3 道部分回答题和 3 道冲突题计入主召回指标。以宏平均 Recall@K 衡量证据覆盖，以 MRR@K 衡量首条证据的排名，单列冲突题双方证据的覆盖情况。
- 3 道澄清题单列诊断候选。2 道明确拒绝题验证指定制度被拒绝且无切片返回。3 道证据不足题单列，其中 Q049 核查受限证据未进入结果。全量评测同时核查结果中无越权和失效版本切片。澄清和证据不足的最终判断属于后续问答评测。
