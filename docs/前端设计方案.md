# 星云科技有限公司企业制度问答系统 · 前端设计方案

版本 0.2，实施基线。用户已于 2026-11-08 确认。首版本地实现与联调已完成。

## 使用目标与首版范围

面向使用公司账号登录的员工。用户从登录页进入制度问答工作台，直接输入问题或从常用问题起步。每轮回答展示查询日期、回答状态和对应制度依据，用户可在对话中补充条件或开始新问题。

| 需求 | 首版设计与验收条件 |
| --- | --- |
| R-01 登录 | 使用现有公司账号登录。登录失败时保留用户名，给出可操作提示。退出或凭证失效后回到登录页，清除当前身份的界面数据。 |
| R-02 制度问答 | 支持输入问题、选填查询日期、补充条件和发起新问题。可区分等待、回答完成、部分回答、制度冲突、证据不足、需补充条件和权限拒绝。 |
| R-03 查看依据 | 点击已校验回答中的引用，查看制度名称、版本、章节和条款。后端提供页码、段落、表格或行号时展示对应位置。 |
| R-04 响应式布局 | 桌面可同时查看回答与引用，窄屏可通过底部面板打开引用。关键操作可用键盘完成，状态变化可被辅助技术读出。 |
| R-05 实时输出 | 提交后立即显示问题与查询状态。模型生成时逐字显示草稿，服务端校验后替换为正式回答。 |
| R-06 页面内历史 | 当前页面可回看和切换已完成的对话，刷新或退出后清空。 |

## 页面与视觉

### 登录页

桌面采用左右分栏，左侧展示「星云科技有限公司」及简洁的星轨图形，右侧放置标题为「企业制度智能问答平台」的登录卡片。移动端合并成单列。表单包含用户名、密码、密码显示切换和登录按钮。错误放在表单内，提交时显示处理中。

### 问答工作台

| 区域 | 桌面 | 移动端 |
| --- | --- | --- |
| 导航 | 左侧显示品牌、新问题、当前页面的问答记录和账号菜单。 | 顶栏保留品牌、新问题，问答记录与账号入口放入菜单。 |
| 对话 | 中央阅读区。空白页展示差旅报销、请假审批、采购流程等示例，点击填入输入框，由用户确认发送。对话开始后，优先呈现回答、日期和引用标记。 | 单列阅读。输入区贴近底部并适配软键盘和安全区。 |
| 引用 | 点正文中的 `[E1]` 或回答下方的「查看依据」打开右侧面板，定位到当前回答的对应条款。 | 使用可关闭的底部面板，关闭后焦点回到原引用。 |

输入区将「查询日期」收在可展开的查询条件中。未设置时交由后端解析问题中的日期，或采用北京时间当天。澄清期间保持原问题条件。涉及多个日期或日期无效时，引导用户选定查询日期后重发。首版可通过问题正文指定制度，例如「请查阅《员工差旅报销管理制度》」。

视觉建议以白色卡片、浅灰蓝背景 `#F6F8FC`、星云蓝 `#3156B8` 和深蓝灰文字 `#18253A` 为主。星轨图形集中在登录页和首次进入的空白状态。正文保持舒适的中文行距，状态同时用文字和图标表示。登录成功、发送、引用定位等操作使用短反馈，尊重系统减少动态效果的设置。

## 接口与交互契约

| 接口 | 对接方式 |
| --- | --- |
| `POST /auth/login` | JSON 请求传 `username`、`password`，成功返回 `access_token`、`token_type`、`expires_in`。现有凭证有效期为 1 小时。前端清除登录态实现退出。 |
| `POST /rag/ask` | 请求带 `Authorization: Bearer <token>`。`question` 去除首尾空白后为 1–1000 字符，可选 `as_of_date`、`document_id`、`session_id`、`new_question`。按响应中的 `status`、`answer`、`as_of_date`、`citations`、`session_id`、`awaiting_clarification` 渲染。 |
| `POST /rag/ask/stream` | 复用现有请求字段、Bearer 鉴权和问答服务。成功建立连接后返回 SSE，浏览器通过 `fetch` 发送 POST 并读取事件。终态数据沿用现有完整问答响应结构。现有 JSON 路由保留供已有调用方使用。 |
| `GET /health` | 可用于基础连通性检查。问答是否可用以实际问答响应为准。 |

- 前端为新对话生成 UUID，后续在流式请求中沿用。以正式响应的 `awaiting_clarification` 决定是否提示只回复条件。普通 `clarify` 提示带上原问题和条件完整重发。澄清状态在服务端进程内保存 15 分钟，过期或服务重启后需要重发完整问题。
- 点击「新问题」创建新的对话上下文。如果在同一会话显式结束澄清并换题，则提交 `new_question=true`。页面内可回看消息，后端跨轮上下文限于待澄清条件。
- 发送后显示「正在查询制度」，同会话有待处理请求时禁用重复提交。事件归属发起请求的对话和轮次。退出时关闭连接、清理页面内存并忽略该身份的迟到事件。
- `answer` 按正文展示。`partial_answer` 标注「部分回答」。`report_conflict` 显示「制度口径存在差异」，保留双方依据。`insufficient_evidence` 提示「现有制度依据不足」。`access_denied` 以业务状态提示无权访问。引用按本轮 `evidence_id` 解析，仅渲染 API 返回的依据字段。
- 登录 `401` 提示核对账号和密码，问答 `401` 回到登录页。`409` 提示上一条仍在处理。`422` 提示修改对应输入。对明确可重试的模型或检索错误提供手动重试。连接中断且未收到终态时，提示处理结果未确认，提供带原问题和补充条件完整重发的入口。
- 引用面板仅展示响应中的元数据和定位信息。按文件格式显示 PDF 页码、DOCX 段落或表格位置、Markdown 行号。

### 流式生成与校验

流式路线复用现有权限、日期、检索、引用校验、澄清和冲突补查逻辑。DeepSeek Chat Completions 官方接口提供 SSE 增量。实现前先用项目实际配置验证 JSON 模式和流式参数组合，确认能够在模型完成前提取正文，并经过部署代理及时抵达浏览器。[DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)

| 事件 | 浏览器行为 |
| --- | --- |
| `phase` | 根据后端已进入的阶段更新「查询制度」「生成中」或「复核依据」。 |
| `draft_delta` | 追加已解码的正文片段。以「生成中 · 草稿」标识，按小批次逐字呈现。复制回答与引用点击等操作等到正式结果后启用。 |
| `draft_reset` | 清空本轮草稿并提示正在重新生成。沿用现有一次格式纠正策略。 |
| `final` | 原子替换正文、回答状态和引用信息。直接生成的定向澄清、权限拒绝等可直接发送正式结果。 |
| `error` | 清除本轮草稿，保留用户问题并按错误类型提供下一步操作。 |

- 后端增量解析结构化模型响应，只推送 `answer` 中完整解码的文本。对拆开的 UTF-8、JSON 转义和引用标记做边界处理。前端以文本渲染草稿，引用可交互性以正式响应为准。
- 服务端按现有规则检查完整 JSON、完成状态和引用。如果初稿校验失败，先撤下再纠正。若触发冲突补查，显示「复核依据」，补查后的内容通过校验才进入正式结果，仍可沿用已有的已校验首答回退逻辑。
- 建流前的请求错误按 HTTP 状态返回。建流后的失败以 `error` 结束。每个成功完成的请求发出一个 `final`，断线或提前关闭按未完成处理，浏览器不自动重新提交。后端断开时尽快关闭上游连接并释放会话占用，状态更新沿用现有成功与失败语义。
- 部署验证覆盖代理缓冲、心跳与空闲超时。同一会话的并发控制仍由后端负责。界面只播报阶段变化和正式回答，避免读屏逐字重复。

## 构建顺序与验证计划

技术建议为 React + TypeScript + Vite 单页应用，沿用现有 FastAPI。开发阶段使用前端代理访问 API，部署建议同源转发。问答记录放在当前页面内存中。登录凭证建议也放在当前页面内存，刷新后重新登录。

| 工作项 | 依赖 | 计划验证 |
| --- | --- | --- |
| T-01 搭建页面框架和登录链路 | R-01 | 有效和无效凭证、退出、JWT 过期、账号切换。 |
| T-02 验证上游流式契约，新增 SSE 路由 | R-02、R-05 | 使用实际模型配置验证首段增量在上游结束前抵达浏览器。模拟分块、转义、格式纠正、冲突补查、授权失败、断开和并发，并回归原 JSON 接口。 |
| T-03 接入提问、草稿、澄清和页面内记录 | T-01、T-02，R-02、R-05、R-06 | 普通及带日期问答、条件补充、澄清失效、换题、断线恢复、草稿撤下、正式结果替换及刷新或退出清空。 |
| T-04 接入引用与异常结果展示 | T-03，R-03 | 复用评测样例核对 PDF 页码、DOCX 段落或表格、Markdown 行号，检查历史版本、冲突双方证据和权限拒绝。 |

## 本地运行

从项目根目录启动 FastAPI。登录需要有效的 `AUTH_TOKEN_SECRET`（至少 32 字节）。问答沿用现有 SQLite、Qdrant、本地向量模型和 DeepSeek 配置。下面第一行给当前 PowerShell 会话设置临时签名密钥，适用于还未配置密钥的本机测试。已配置密钥时直接运行第二行。

```powershell
$env:AUTH_TOKEN_SECRET = [Convert]::ToHexString([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
.\.venv\Scripts\python.exe -B -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开终端，从项目根目录启动前端并打开 [本地问答工作台](http://127.0.0.1:5173/)。

```powershell
Set-Location frontend
npm ci
npm run dev -- --host 127.0.0.1
```

在 `frontend` 运行 `npm run build` 会生成 `dist`。部署时将静态文件与 `/auth/*`、`/rag/*` 置于同一 HTTPS 域名下，关闭流式路由的响应缓冲。
